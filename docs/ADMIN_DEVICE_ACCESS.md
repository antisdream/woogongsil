# 관리자 접근

확인일: 2026-09-09 · 소스 버전: 2.4.3

## 현재 접근 정책

`https://woogongsil.site/manage`는 누구나 인증서 없이 열 수 있습니다. 관리자 로그인은 정확히 `skn29`인 계정만 허용하며 기존 비밀번호, 관리자 권한과 정지 여부를 함께 검증합니다. 홈페이지에는 관리자 링크를 표시하지 않습니다.

비로그인 관리자 API는 401, 허용되지 않은 계정·잘못된 비밀번호도 401로 거부합니다. 다른 관리자 계정의 이전 세션은 폐기합니다. HttpOnly·SameSite 세션 쿠키, 세션 만료·폐기, Origin·CSRF 검사, 로그인 요청 제한은 유지합니다. 기존 결재 반영의 내부 재호출도 loopback·비밀 토큰·외부 전달 주소 검사를 유지합니다.

2.4.2에 도입한 기기 인증서 제한은 취소했습니다. Express와 Vite 개발·미리보기 서버에서 인증서 검사를 제거하고 `/manage`의 별도 관리자 화면 경로 처리는 유지합니다. Windows·휴대폰의 인증서 설치나 선택은 현재 관리자 접속의 선행 조건이 아닙니다.

## 운영 적용과 복구

1. 인증서 없는 로컬 로그인 화면과 `skn29` 로그인, 다른 계정 거부, 세션·CSRF 검사를 확인합니다.
2. 대상 소스만 커밋·푸시하고 서버 앱·DB·Nginx·설정 전체 백업과 체크섬을 검증합니다.
3. 정식 GitHub 릴리즈를 발행하고 공개 로그인 HTML 200, 비로그인 관리자 API 401, 버전·커밋을 확인합니다.
4. 기존 Nginx의 `ssl_client_certificate`, `ssl_verify_client`, `ssl_verify_depth` 및 `X-WGS-Admin-*` 전달 설정만 제거합니다. 기존 HTTPS 서버 인증서와 다른 프록시 설정은 유지합니다. 적용 전 원본 해시를 대조하고 후보 설정의 `nginx -t` 통과 후 reload합니다. 실패하면 보관한 원본을 복원합니다.
5. 외부 HTTPS에서 클라이언트 인증서 없이 관리자 로그인 화면을 열 수 있고, 비로그인 API가 401인지 확인합니다.

정상 2.4.3은 `/home/ubuntu/wgs_deploy/admin-access`의 기기 정책·인증서를 사용하지 않습니다. 기존 파일은 직전 2.4.2로 복구할 경우를 위해 비공개로 보존하며 GitHub나 릴리즈에 첨부하지 않습니다. 배포 복구 검사만 이전 인증서 제한 응답도 처리합니다. 서버에는 기기의 개인 키를 추가하지 않습니다.

## 검증 범위

백엔드 회귀 검사에는 실제 로컬 HTTP와 bcrypt를 사용한 `skn29` 로그인, 다른 관리자·대소문자가 다른 계정·미등록 계정·잘못된 비밀번호·정지 계정 거부, 인증서 헤더 없는 세션 조회, 위조 헤더 거부, Origin·CSRF 검사, 로그아웃 후 재사용 거부가 포함됩니다. 저장소는 시험용 메모리 저장소이며 운영 DB나 실제 운영 비밀번호를 사용하는 검사는 아닙니다.

배포 검사는 공개 로그인 HTML 200·비로그인 API 401을 요구하며 기기 정책 파일이 없어도 통과해야 합니다. 실패한 배포의 이전 소스·화면 복원과 기존 방문 합계 공개 범위도 검사합니다. Android 네이티브 소스와 APK는 이번 변경 대상에 포함하지 않습니다.
