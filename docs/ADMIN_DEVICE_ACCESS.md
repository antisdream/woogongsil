# 관리자 기기 접근

확인일: 2026-09-09 · 소스 버전: 2.4.2

## 접근 정책

홈페이지에는 관리자 진입 링크가 없습니다. 승인된 노트북 또는 Galaxy S26 Ultra의 Chrome에서 `https://woogongsil.site/manage`를 직접 입력합니다. 기기별 TLS 클라이언트 인증서를 먼저 확인한 뒤 로그인 화면을 제공하며, 그다음 `skn29` 계정의 비밀번호·관리자 권한을 확인합니다.

`/manage`, 하위 경로·직접 HTML 경로와 `/api/admin`은 인증서가 없거나 승인되지 않으면 404입니다. URL 인코딩·대소문자 변형도 검사합니다. 관리자 세션을 다른 기기로 복사해도 인증서 확인을 통과해야 하며, 다른 관리자 계정의 이전 세션은 폐기합니다. IP·User-Agent·일반 방문자 ID를 기기 승인 수단으로 사용하지 않습니다.

Express는 정적 HTML과 라우트보다 먼저 기기를 검사합니다. Vite 개발·미리보기 서버에도 같은 인증서 검사를 적용합니다. `/api/admin` 밖에서 기존 관리자 인증 헬퍼를 사용하는 경로 역시 승인 기기를 요구합니다. 기존 결재 반영의 서버 내부 재호출은 loopback·비밀 토큰·외부 전달 주소 부재 검사를 유지합니다.

## 인증서와 보관

- 노트북: Windows 사용자 인증서 저장소의 TPM 키를 사용합니다. 개인 키 내보내기를 허용하지 않습니다.
- 휴대폰: 해당 기기에 발급한 암호화 `.p12` 인증서를 VPN 및 앱 사용자 인증서로 설치합니다. Chrome이 인증서를 요청하면 우공실 관리자 인증서를 선택합니다.
- 휴대폰 설치 파일과 설치 암호를 함께 복제하면 다른 기기에서도 같은 인증 자격을 사용할 수 있습니다. 휴대폰 접속 확인 후 전달용 파일·암호 사본을 제거하고, 유출·분실 시 즉시 승인 목록을 교체합니다. 휴대폰 키의 하드웨어 생성·기기 증명까지 검증한 구조는 아닙니다.
- 발급 인증서 만료일은 2028-09-09입니다. 만료 전에 교체합니다. 브라우저·네트워크 변경으로 IP가 바뀌어도 인증서는 사용할 수 있습니다.

서버에는 CA 공개 인증서, 두 기기의 공개 인증서와 SHA-256 승인 목록, Nginx→Node 전달 비밀값만 저장합니다. 기기의 개인 키와 설치 암호는 서버·GitHub·릴리즈 첨부에 포함하지 않습니다. Chrome의 인증서 선택은 TLS 연결 단계에서 발생하므로, 승인 기기에서는 같은 사이트의 공개 페이지를 처음 열 때 선택창이 나타날 수도 있습니다.

## 서버 설정

설정 디렉터리는 `/home/ubuntu/wgs_deploy/admin-access`이며 디렉터리 0700, 파일 0600을 적용합니다. 기본 정책 파일은 `policy.json`이고, 별도 로컬 환경에서는 `WGS_ADMIN_DEVICE_POLICY_FILE`로 경로를 지정합니다. 정책의 `version`은 1, `gatewaySecret`은 32바이트 난수의 64자리 hex, `devices`는 서로 다른 SHA-256 인증서 지문 두 개입니다. 설정이 없거나 잘못되면 접근을 차단합니다. 정책은 요청마다 다시 읽으므로 승인 교체가 즉시 반영됩니다.

Nginx HTTPS 서버에 `ssl_client_certificate`, `ssl_verify_client optional`, `ssl_verify_depth 1`을 설정합니다. 공개 홈페이지는 인증서 없이 사용할 수 있습니다. 프록시는 `X-WGS-Admin-Gateway`, `X-WGS-Admin-Verify`, `X-WGS-Admin-Certificate`를 서버 설정과 `$ssl_client_verify`, `$ssl_client_escaped_cert`로 덮어씁니다. 외부에서 같은 이름의 헤더를 보내도 사용하지 않습니다. Node는 loopback 연결·전달 비밀값·TLS 검증 결과·인증서 지문·유효기간·클라이언트 인증 용도를 함께 확인한 뒤, 전달 헤더를 지워 일반 핸들러나 요청 로그로 유출하지 않습니다.

Nginx의 TLS 검사는 [공식 SSL 모듈 문서](https://nginx.org/en/docs/http/ngx_http_ssl_module.html#ssl_verify_client)를 따릅니다. 관리자 API 포트는 운영에서 loopback으로 제한합니다. 정책 파일의 비밀값을 환경 예시·명령 출력·배포 로그에 넣지 않습니다.

## 배포와 복구

1. 로컬 접근 경계·계정·세션·화면 검사와 두 기기의 인증서 설치를 확인합니다.
2. 지정 경로만 커밋·푸시하고 서버의 앱·DB·설정 전체 백업을 검증합니다.
3. 공개 인증서와 정책을 서버에 안전하게 설치하고, Nginx 후보 설정의 `nginx -t`를 확인한 후 적용합니다. 기존 설정과 파일 권한을 복구본으로 보관합니다.
4. 정식 GitHub 릴리즈를 발행하고, 승인 없는 HTML/API 404와 승인된 기기의 로그인 HTML 200·비로그인 API 401, 운영 버전·커밋을 확인합니다. 서버 내부 건강 검사는 전달 비밀값과 공개 인증서로 Node 경계를 검사하며 기기 개인 키를 보관하지 않습니다. 외부 TLS 검사는 별도로 수행합니다.
5. 두 기기 Chrome에서 관리자 로그인, 인증서 없는 브라우저의 차단, 공개 학습 화면을 확인합니다.

인증서 분실·만료 때는 기존 Lightsail SSH 관리 경로에서 새 인증서를 등록합니다. 임시 공개 로그인이나 IP·User-Agent 우회는 만들지 않습니다. 소스 원복이 기기 제한 도입 이전 버전으로 돌아가면 이전 인증 경계가 복원되므로, 원복 후 적용 상태를 별도로 확인해야 합니다.

## 이번 검증의 범위

백엔드 137개, 프런트엔드 22개, 배포·복구 8개, 로컬 실제 Nginx HTTPS 검사 35개와 화면 검사 97개를 통과했습니다. 노트북 TPM 키의 실제 TLS 서명과 발급한 휴대폰 인증서의 TLS 통신을 확인했습니다. HTTPS 로그인 검사는 격리된 메모리 시험 저장소를 사용했고, 화면 검사는 API·소켓을 합성 응답으로 대체했습니다. 이를 운영 DB 로그인이나 실제 휴대폰 Chrome 접속 완료로 해석하지 않습니다. 최종 기기·운영 확인은 배포 결과 기록에서 별도로 남깁니다.

이번 변경은 Android 네이티브 코드를 바꾸지 않습니다. 기본 APK의 공개 웹은 운영 사이트를 사용하고, 과거 웹을 포함한 debug APK는 새 웹으로 다시 빌드해야 화면 정리가 반영됩니다. 관리자 접속은 지정된 두 기기의 Chrome을 대상으로 합니다.
