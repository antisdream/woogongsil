# 우공실 2.4.5·2.4.6 보안 보완과 검증

작성일: 2026-09-10. 기준 버전은 2.4.4, 기준 커밋은 `3357f8220791a720e4ab70bbdbb411b7ebed382f`다. S01~S08과 통합 검증을 먼저 마친 뒤 A01~A07을 진행했다. 기존 서버에서 적용하며 인스턴스 증설, AWS 스냅샷 추가, 신규 유료 서비스 구매는 포함하지 않는다.

## 변경 범위

| 단계 | 반영 내용 | 사용자에게 보이는 변화 |
|---|---|---|

| A04 | 운영 HTTP·Socket.IO 출처 제한 | 허용한 사이트 출처의 브라우저만 인증 통신 가능 |

| A06 | Ubuntu UFW·SSH 설정과 시간 제한 복구 | 키 로그인 유지, 비밀번호·root 로그인·전달 기능 차단; 새 SSH 연결 확인 후 확정 |
| A07 | 원문 없는 보안 이벤트와 로그 보존량 제한 | 비밀번호·인증번호·쿠키·이메일·본문·URL 인수를 새 로그에 남기지 않음 |

회원의 기존 저장 토큰은 배포 시 전체 삭제하지 않는다. 배포 이후 24시간의 고정된 전환 기간에 계정별 1회 쿠키 교환을 허용하고 이전 토큰을 소비한다. 기간 종료·폐기·비밀번호 변경 뒤에는 다시 로그인해야 한다. 관리자 OTP 쿠키는 회원 쿠키와 별도로 유지한다.

실기 자기확인 문항은 자동 검증 점수로 인정하지 않고 미검증으로 표시한다. 기존 학습 기록 파일은 보존한다. 파일 시그니처 검사는 전체 악성코드 검사 서비스가 아니며, 기존 SVG 원본과 소유권이 불명확한 첨부를 삭제하지 않는다.

각 단계의 반복·포함 검증은 서로 독립된 전체 건수로 합산하지 않는다. 최종 검증은 Windows의 격리된 작업 폴더, 운영과 같은 Node 22.22.2, 실제 임시 MySQL, 운영 DDL과 합성 계정·문제로 실행했다.

메일은 격리된 수신 대역과 합성 데이터로 검사했다. 위 수치는 운영 사용자의 실제 받은편지함 수신·비밀번호 입력·업무 쓰기, 장기간 운영 부하 또는 Google Play 심사 결과를 의미하지 않는다. 로컬 릴리즈 검사에서 PM2 재시작은 모의 실행했으며 운영 재시작은 아래 배포 확인에서 별도로 기록한다.

Android Lint 경고는 `OldTargetApi` 1개, `GradleDependency` 2개, `ModifierParameter` 1개, `ObsoleteSdkInt` 1개다.

## 배포와 복구 절차

1. 작업별 한글 `작업일자|작업내용` 커밋을 원격 main에 반영하고 SHA를 확인한다. GitHub 정식 `v2.4.5` 릴리즈 발행이 배포를 시작한다.
2. 기존 릴리즈 도구가 서버 안에 변경 대상 코드·환경 복구본과 논리 DB 백업을 만들고 압축 무결성을 확인한다. 이는 AWS 스냅샷 추가가 아니다. 런타임 파일·업로드·문제 이미지·폰트를 보존한다.
3. 검증된 의존성과 웹 파일을 준비한 후 앱을 잠시 중지한다. 별도 마이그레이션 계정으로 스키마를 적용하고 제한된 실행 계정을 구성한다. 과거 JSON의 재수입은 실행하지 않는다.
4. 보호된 앱 환경을 갱신하고 PM2에 새 환경을 적용한다. Nginx 요청 제한을 관찰 모드로 먼저 검사한 뒤 활성화하고 직접·외부 HTTPS 상태와 배포 SHA를 확인한다.
5. 앱·환경·프록시 반영이 실패하면 이번 변경 범위의 코드·의존성·웹·환경·Nginx를 복구한다. 전체 운영 DB를 과거 덤프로 덮어쓰지 않는다. MySQL DDL은 전체 롤백되지 않으므로 완료 버전이 없는 단계는 멱등 재실행으로 복구한다.
6. 웹 배포 확인 뒤 UFW·SSH를 적용한다. 180초 자동 복구 타이머를 먼저 시작하고 새 SSH 연결·외부 HTTPS를 확인한 뒤 150초 안에 확정한다.
7. 실제 GitHub 배포 웹 묶음의 파일 해시·버전·커밋을 확인하여 Android APK에 포함한다. 같은 서명·더 높은 버전으로 Z Flip4에 데이터를 지우지 않고 업데이트하고 설치 APK 해시와 실제 화면을 확인한다.

실행 계정에는 CREATE·ALTER·DROP·임시 테이블·FILE·SUPER·GRANT OPTION 및 다른 DB 권한을 부여하지 않는다. 마이그레이션 자격 증명과 로그 HMAC 키는 공개 저장소·APK·명령 인수·보고서에 포함하지 않는다. 자세한 절차는 [DB 안내](../ops/mysql/README.md), [요청 제한](../ops/nginx/README.md), [HTTPS 정책](../ops/nginx/HTTPS_POLICY.md), [출처 정책](../ops/nginx/ORIGIN_POLICY.md), [서버 접근](../ops/security/README.md), [로그 정책](../ops/security/LOGGING.md)에 기록한다.

## 운영·기기 확인 상태

이 문서의 최초 커밋 시점에는 로컬 검증만 완료했다. 릴리즈 배포와 실제 기기 설치 결과는 실행 뒤 별도 결과 절에 추가한다. Lightsail 콘솔 방화벽·콘솔 복구 권한은 확인되지 않았으며 Ubuntu 호스트의 접근 설정과 구분한다.

### v2.4.5 배포 준비 실패와 v2.4.6 재시도

GitHub 검사·웹 빌드·패키지는 성공했으나 DB 백업 도구가 앱 밖의 환경 파일을 기준으로 `dotenv`를 찾으면서 준비 단계에서 멈췄다. 앱 교체·중지·마이그레이션 전이었다. 실제 운영 버전은 v2.4.4, PM2 상태는 online, 재시작 횟수 153으로 배포 전과 같음을 확인했다.

백업 프로세스에만 기존 백엔드의 모듈 탐색 경로를 명시했다. 운영 자격 증명 파일과 공용 환경은 그대로 유지한다. 별도 디렉터리의 환경 파일에서 Node 모듈 탐색 실패를 재현하고 복구하는 검사를 추가하여 릴리즈 Python 검사 15/15를 통과했다. 이 검사는 Windows에서도 UTF-8 모드로 실행했다. 공개한 v2.4.5 태그는 변경하지 않고, 수정과 Android 버전을 포함한 v2.4.6 릴리즈로 다시 배포한다.
