# 우공실 조회 제한 설정

공개 학습을 유지하면서 반복 요청을 줄이는 설정이다. 서버 증설·스냅샷·유료 WAF를 사용하지 않는다.

`wgs-rate-zones.conf`는 `http` 범위에서 한 번만, `wgs-rate-server.conf`는 우공실 HTTPS `server` 범위에서 포함한다. 기존 인증서·프록시·도메인 설정은 배포 스크립트에서 보존해야 한다. 적용 전 `nginx -t`가 실패하면 reload하지 않는다.

| 대상 | 기본 제한 |
|---|---|
| Nginx API 요청 | IP당 초당 30건, 순간 추가 120건 |
| Nginx 문제 조회 | IP당 초당 10건, 순간 추가 60건 |
| 진행 중인 API 요청 | IP당 120개 |
| 앱 API 조회 | IP당 분당 1,200건 |
| 앱 문제 조회 | IP당 분당 600건, 제시한 회원 세션별 60건 |
| 새 응시 발급 | 실제 회원/게스트 응시 주체별 분당 30건, DB에서 확인 |
| 문제 범위 | 필기·실기 회차당 최대 200개, 3주 공략 페이지당 100개 |

Nginx의 IP 제한은 접속 주소를 기준으로 한다. 클라이언트가 전달한 사용자 이름이나 `X-Forwarded-For`를 바꾸어도 IP 제한이 해제되지 않는다. 앱 요청 제한 메모리는 최대 10,000개 항목으로 제한된다. 정적 파일은 API 제한의 대상이 아니다.

로컬에서는 운영과 같은 버전인 공식 Windows Nginx 1.24.0으로 문법 검사, `limit_req_dry_run on` 관찰, 429 응답, 재시도, 같은 IP의 50명 동시 조회를 확인했다. Linux 운영 트래픽의 부하 시험을 대체하지 않는다. 최초 운영 적용에서도 관찰 결과와 정상 기능 점검 후 제한을 활성화한다. 분산된 여러 IP에서의 모든 크롤링을 막는 설정은 아니다.

운영 시 429가 정상 사용을 방해하면 실패 경로와 공유 네트워크 상황을 확인하고 한도를 조정한다. 인증·게시글 권한·파일 권한을 완화해서 해결하지 않는다.

근거: [Nginx 요청 제한 모듈](https://nginx.org/en/docs/http/ngx_http_limit_req_module.html), [연결 제한 모듈](https://nginx.org/en/docs/http/ngx_http_limit_conn_module.html).
