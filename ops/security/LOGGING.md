# 보안 이벤트와 운영 로그

새 보안 이벤트는 고정된 종류·결과·시간·HTTP 상태와 HMAC 처리한 계정/IP 식별값만 저장한다. 비밀번호, 인증번호, 쿠키, 세션 토큰, 이메일 원문, 요청·응답 본문, 검색어, URL 인수, User-Agent는 저장하지 않는다. 해시 식별값도 제한된 운영 정보로 취급한다.

- 운영 `WGS_SECURITY_LOG_DIR`은 `/home/ubuntu/wgs_deploy/security-logs`로 지정한다. 디렉터리는 0700, JSONL 파일은 0600이다. `WGS_SECURITY_LOG_SECRET`은 앱 외부의 보호된 환경 설정에 새 난수를 저장한다. Git·명령 인수·로그에 넣지 않는다.
- 이벤트 파일은 UTC 날짜·크기로 분리하고 파일당 2MiB, 최대 5개, 최대 14일을 유지한다. 파일 개수와 나이는 기록 시 확인하므로 요청이 없는 동안에는 기존 파일을 읽거나 노출하지 않는다. 큐 256개·분당 180개 상한을 넘기면 원문 대신 누락 개수만 나중에 남긴다. 이 한도 때문에 모든 공격 요청이 개별 보존된다는 주장은 하지 않는다.
- 실제 서버 모듈의 진단 출력은 고정된 소스 식별자와 제한된 오류 코드만 기록한다. SQL/SMTP 오류의 message·stack·response나 객체 전체를 출력하지 않는다. 예기치 않은 예외도 내용을 노출하지 않고 종료하여 PM2가 재기동할 수 있게 한다.
- Nginx 접근 기록은 `wgs-log-format.conf`를 사용한다. 경로는 admin/api/attachment/realtime/page 분류로 줄이고 메서드도 허용된 값만 기록한다. 원본 URI·IP·헤더는 기록하지 않는다. 해당 사이트의 Nginx 상세 오류 출력은 `/dev/null`로 보내고 HTTP 상태·응답 시간과 앱의 오류 코드로 장애를 확인한다.
- PM2의 우공실 로그와 Nginx 새 접근 로그는 별도 systemd 타이머가 매분 logrotate로 점검한다. 파일당 회전 기준 2MiB, 이전 파일 5개, 최대 나이 14일이다. 회전 점검 사이의 유입량만큼 기준을 초과할 수 있다. `copytruncate` 방식의 PM2 회전은 매우 짧은 구간의 진단 로그 누락 가능성이 있다.
- 기존 관리자 업무 이력과 개인정보 열람 증적은 기존 보존 정책을 따른다. 이번 변경으로 과거 업무 기록을 삭제하거나 이미 남아 있는 정보를 소급해 제거하지 않는다. 기존 PM2 로그 접근 권한은 제한한다.

SMTP/SQL 예외 원문, 인증 입력, 헤더, 잘못된 JSON 요청을 포함한 합성 테스트로 원문이 기록되지 않는지 확인한다. 디스크 쓰기 실패는 로그인 요청을 연쇄 실패시키지 않도록 처리하고, 진단 코드와 로그 상태로 구분한다. 로그만으로 과거 침해 여부나 모든 행위의 무결성을 증명할 수는 없다.
