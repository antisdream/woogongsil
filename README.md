# 우공실

우공실은 정보처리기사 필기·실기를 공부하는 웹 학습 서비스입니다. 문제를 풀고 해설을 확인한 뒤, 회원 계정에 저장한 기록과 오답으로 복습을 이어갈 수 있습니다. PC와 휴대폰 브라우저에서 같은 사이트를 이용합니다.

- [우공실 서비스](https://woogongsil.site)
- [화면 설계 기준](./DESIGN.md)
- [변경 이력과 검증 범위](./PATCH_NOTES.md)

이 문서는 2026-09-07 소스 기준입니다. 신규 UI의 운영 반영 여부는 해당 날짜의 변경 이력에서 별도로 구분합니다.

## 학습과 주요 화면

| 기능 | 경로 | 할 수 있는 일 |
|---|---|---|
| 홈 | `/` | 학습 안내, SQL 예제, 회원 접속 현황, 공지와 이용 안내, 모바일 접속 QR |
| 정보처리기사 | `/cert/ipe` | 필기·실기 학습 방식 선택 |
| 필기 | `/cert/ipe/written`, `/cert/ipe/written-bank`, `/cert/ipe/written-past` | 문제은행, 기출 회차 선택, 답안·해설·채점 결과 확인 |
| 실기 | `/cert/ipe/practical`, `/cert/ipe/practical-bank`, `/cert/ipe/practical-past`, `/cert/ipe/practical-three-week` | 주관식 문제은행, 기출, 3주 공략, 문제 이미지와 특수기호 답안 입력 |
| 오답 복습 | `/wrong` | 계정에 저장된 필기·실기 오답 확인과 다시 풀기 |
| 멀티플레이 CBT | `/multiplayer` | 방 생성·참여, 함께 응시, 결과·기록·오답 확인 |
| 내 정보 | `/mypage` | 개인 정보, 시험 목표일, 계정 관리와 회원탈퇴 |
| 학습노트 | `/study` | 폴더·문서, 공개 범위, 오답 삽입, 임시저장과 불러오기·복구 |
| 게시판 | `/board/notice`, `/board/free` | 공지·자유글, 문서 편집기, 이미지·파일 첨부, 검색·댓글·추천·임시저장 |
| 계정 | `/login`, `/signup`, `/find`, `/change-pw` | 로그인, 회원가입 신청, 계정 찾기, 비밀번호 변경 |

| 추가 서비스 | `/fortune` | 별도 개인정보 동의 흐름을 포함한 운세 |
| 운영 관리 | `/manage/login` | 일반 회원 화면과 분리된 관리자 로그인 |

기존 `/written`, `/practice`, `/exam`, `/ipep` 주소는 해당 정보처리기사 경로로 이동합니다. 맛집 지도와 캘린더 일정 관리는 현행 라우트와 메뉴에서 제외되어 있습니다. 과거 변경 이력에는 당시 기능 설명이 남아 있습니다.

문제를 공부하고 기록을 이어가는 보조 기능도 제공합니다.

- 필기·실기 문제 화면의 오류신고로 문제 정보와 오류 내용을 전달할 수 있습니다. 신고·공지 등의 이메일 알림 기능은 실제 메일 전송 결과와 구분해 확인합니다.
- 게시판은 BlockNote 문서 편집기와 이미지·파일 첨부를 지원합니다. 첨부는 회원 세션과 파일 종류·크기 제한을 확인하며, 임시저장한 글을 다시 불러올 수 있습니다.
- 로그인한 회원은 현재 접속 현황을 확인할 수 있습니다. 공개 홈에는 모바일 접속 주소·QR을 제공하며, 다크·라이트 테마와 화면 밝기를 조절할 수 있습니다.
- 오늘·누적 방문 수와 관리자 방문 통계를 제공합니다. 방문 세션 수, 실시간 접속자, 로그인 이력은 집계 의미가 다릅니다.

## 공개 접속과 회원 기능

현재 사이트는 별도 입장코드나 hCaptcha 없이 접속합니다. 홈, 홈페이지의 설명용 SQL 예제, 공지 열람, FAQ와 법적 안내를 확인할 수 있습니다. 홈페이지 예제 결과는 개인 학습 기록에 저장되지 않습니다.

홈의 학습 시작 버튼은 비회원에게 로그인 화면을, 회원에게 학습 선택 화면을 엽니다. 상단 메뉴의 학습·개인 기능도 비회원에게 로그인을 안내합니다. 일부 학습 주소를 직접 열어 문제를 보거나 연습할 수 있어도 회원 기록이 생성되었다는 뜻은 아닙니다. 개인 기록 조회·저장, 오답 관리, 학습노트, 멀티플레이, 자유게시판과 글·댓글·추천 등은 각 기능의 회원 세션과 권한 검사를 따릅니다.

- 로그인에는 세션 만료·중복 로그인 확인과 최신 약관·개인정보 동의 절차가 있습니다.
- 구형 클라이언트의 게이트키퍼 호환 API는 남아 있지만 현재 입장코드·CAPTCHA를 요구하지 않습니다.
- 요청 제한, 허용 출처 검사, 보안 헤더와 개별 API의 권한 검사는 별도로 유지합니다.

## 회원가입 절차

공개 접속으로 바뀐 것과 가입 자동승인은 별개입니다. 현재 가입 API에는 자동가입·자동승인 전환 설정이 없으며, 회원가입 신청은 관리자 승인 대기로 접수합니다.

1. 이용약관·개인정보 동의와 만 14세 이상 확인을 완료합니다.
2. 회원 정보를 입력하고 아이디 중복 확인과 이메일 인증을 진행합니다.
3. 서버가 신청과 동의 이력을 저장하고 승인 대기 상태를 반환합니다.
4. 관리자가 승인하면 계정이 생성되어 로그인할 수 있습니다. 거절 시에는 사유를 포함한 안내 메일 발송을 시도합니다.

관리자 알림이나 결과 안내 메일의 발송 여부는 신청 접수·승인 상태와 구분합니다. 화면 문구 설정만 바꿔도 서버의 가입 정책이 바뀌지는 않습니다.

## 관리자 화면

관리자는 `/manage/login`에서 별도로 로그인합니다. 일반 회원의 브라우저 저장소에 있는 역할 표시를 관리자 인증 수단으로 사용하지 않습니다. 서버가 관리자 권한을 확인한 뒤 HttpOnly 세션 쿠키를 발급하며, 관리자 변경 요청에는 CSRF 검증을 적용합니다.

관리자 화면은 대시보드, 사용자·접속 관리, 방문 통계, 회원가입 승인, 운영자 결재, 공지·점검 관리, 문제·해설 관리, 화면 설정으로 구성됩니다. 민감 정보 조회·회원 조치·승인과 같은 기능은 기존 권한과 사유 입력 절차를 따릅니다.

회원 목록의 이름·이메일은 마스킹합니다. 개인정보 원문은 최고관리자 권한, 비밀번호 재인증과 열람 사유를 확인한 뒤 제한적으로 보여줍니다. 운영자 요청의 승인·반려와 가입 승인·거절은 각각의 관리 화면에서 처리합니다.

회원 목록의 최근 로그인은 로그인 API가 성공한 시각이고, 최근 로그아웃은 명시적인 로그아웃 호출 기록입니다. 브라우저·탭 종료나 서버 재시작이 항상 로그아웃으로 기록되는 것은 아니므로 로그인 유지 상태, 실시간 접속, 방문 세션 통계를 서로 구분해 해석합니다.

## 기술과 구조

프런트엔드는 React 19, Vite 8, React Router 7, Axios, Socket.IO Client, BlockNote/Mantine, React Icons를 사용합니다. 백엔드는 Node.js, Express 5, MySQL, Socket.IO, bcrypt, Nodemailer로 구성합니다. 운영 환경은 AWS Lightsail의 Ubuntu, Nginx, PM2와 MySQL입니다. 정확한 의존성 버전은 각 `package-lock.json`을 기준으로 합니다.

```text
backend/
  config/          환경 변수·DB 연결
  middleware/      요청 제한과 구형 접속 API 호환
  routes/          회원·관리자·학습·게시판 등 API
  services/        인증·동의·통계·저장소와 공통 로직
  scripts/         데이터 적재·유지보수 도구
  server.js        Express·Socket.IO 진입점
frontend/
  manage/          관리자 HTML 진입점
  public/          공개 정적 파일
  src/
    admin/         독립 관리자 앱·로그인·세션
    components/    공통 UI
    features/      기능별 모듈
    pages/         라우트 화면
    styles/        공통·기능·관리자 스타일
DESIGN.md
PATCH_NOTES.md
README.md
```

## 로컬 실행과 확인

개발용 MySQL과 메일 등 필요한 설정을 준비하고, `backend/.env.example`을 참고해 별도의 `backend/.env`를 구성합니다. 공개 저장소에 운영 DB, 계정, 사용자 업로드와 전체 문제 이미지가 포함되어 있지는 않으므로 소스 설치만으로 운영과 동일한 데이터가 나타나지는 않습니다.

백엔드 터미널:

```bash
cd backend
npm ci
npm run check
npm start
```

프런트엔드 터미널:

```bash
cd frontend
npm ci
npm run dev
```

기본 개발 주소는 `http://localhost:5173`이며 API·Socket.IO·문제 이미지 요청은 Vite 프록시를 통해 `http://localhost:5000`으로 전달합니다. 관리자 개발 화면은 `http://localhost:5173/manage/login`입니다. 빌드에는 일반 화면과 관리자 화면의 HTML 진입점이 모두 포함됩니다. Windows PowerShell에서 npm 스크립트 실행이 정책에 막히면 같은 명령을 `npm.cmd`로 실행할 수 있습니다.

기본 검증:

```bash
cd backend
npm run check
node --test
```

```bash
cd frontend
npm run lint
node --test
npm run build
```

백엔드의 `npm test`는 문법 검사인 `npm run check`를 실행하므로 단위 테스트 실행과 구분합니다. 헬스 응답은 `/api/ipep/health`에서 확인할 수 있지만, 이것만으로 로그인·저장·메일·멀티플레이 전체 흐름이 검증되지는 않습니다.

환경 설정은 서버·DB 연결, 사이트 URL·허용 출처, 메일, 관리자 세션 쿠키·만료·권한, 방문 통계의 해시·캐시, 동의와 요청 제한 범위를 포함합니다. `.env.example`에는 구형 입장코드·hCaptcha·지도 항목도 남아 있으므로 현행 기능에 필요한 값은 실제 설정을 읽는 소스와 대조합니다. 실제 비밀값과 운영 데이터를 공개 저장소에 추가하지 않습니다.

## 검증 범위와 배포 구분

1차 UI의 로컬 검사 결과는 합성 브라우저 검사 **742/742**, 백엔드 단위 검사 **86/86**, 프런트엔드 단위 검사 **17/17** 통과입니다. 백엔드 문법 검사, 전체 ESLint, 프런트엔드 빌드와 Git diff 공백 검사도 통과했습니다. 브라우저 검사 수는 실제 사용자나 기기 수가 아니라 합성 환경의 검사 항목 수입니다.

2026-09-07 UI는 로컬 React 화면에 합성 API 응답을 연결해 확인했습니다. PC·모바일 폭, 주요 반응형 경계, 긴 내용·빈 목록·오류 상태, 선택·입력·채점 표시, 게시판 이동·편집 복원, 관리자 탐색과 일부 대화상자를 검사했습니다. API·Socket.IO·외부 연결을 가로챈 테스트이므로 운영 DB 저장, 실제 계정 가입·승인·메일, 여러 실제 사용자의 동시 접속까지 입증하는 결과는 아닙니다.

1차 운영 반영 전 전체 백업을 완료하고 백업 파일 24개의 체크섬과 DB 49개 테이블을 검증했습니다. 프런트엔드 소스 68개와 빌드 결과를 반영했고, 삭제 파일·서버 재시작은 각각 0건이며 배포 확인 구간의 서버 로그에 추가 오류가 없었습니다. 운영 비회원 브라우저 검사는 지정 화면·뷰포트 17개에서 **190/190** 통과했고, 실제 로드한 배포 자산 18개의 SHA-256이 빌드와 일치했습니다. 쓰기·회원 조회·Socket·외부 연결은 차단했으며 정상 비회원 401 응답은 오류와 구분했습니다.

1차 APK 버전의 실제 Android 검사에서는 운영 홈의 **360×800** 화면과 비회원 접속을 확인했습니다. 입력창에 초점을 맞추고 키보드를 표시해 화면 높이가 약 **476px**로 줄어든 뒤에도 입력창이 보이는 것을 확인했습니다. 자격증명 입력이나 로그인 제출은 하지 않았습니다. 1차 APK 패키지는 포함된 웹 자산 **395개**가 운영 파일과 일치하고 CRC 검사를 통과했으며, 관리자 HTML은 포함하지 않은 것으로 확인했습니다.

최종 보완에서는 빈 홈 보조 문구의 장식점과 터치 후 남는 hover 강조를 두 소스 파일에서 수정했습니다. 보완 합성 검사 **19/19** 통과 후 새 전체 백업의 체크섬 **24파일**과 DB **49테이블**을 검증하고 운영에 반영했습니다. 배포된 정적 파일 **446개**의 SHA-256을 검증했으며, PM2 프로세스 ID·누적 재시작 횟수는 유지되고 배포 확인 구간의 추가 오류는 0건이었습니다.

최종 APK 번들 `mobile-ui-20260907T131549488Z`의 웹 자산 **395개**가 운영과 일치하고 CRC 검사를 통과했습니다. 실제 Galaxy Z Flip4에 새 APK를 설치·실행해 **360×800** 화면, 가로 넘침 없음, 빈 장식점 제거와 비활성 하단 메뉴 3개의 투명한 배경을 확인했습니다. 앞의 키보드 **476px** 측정은 1차 APK 버전에서 수행한 결과이며 최종 버전에서 다시 측정한 값은 아닙니다.

위 결과는 운영 회원의 가입·승인·메일·데이터 저장·여러 사용자의 동시 시험이나 Android 회전·네이티브 전체화면·모든 기기의 APK 설치 호환성을 검증한 결과는 아닙니다. 학습 합성 테스트의 네이티브 전체화면 API도 화면 크기 조절을 위해 대체했습니다. 기능의 코드 존재, 합성 테스트, 운영 비회원 표시, 실제 기기 입력창 표시, APK 파일 일치의 근거를 각각 구분합니다.

운영 소스와 일치하도록 백엔드·프런트엔드 기준선을 정리한 뒤 UI를 변경했습니다. 서버의 1차·최종 보완 UI 배포 범위는 프런트엔드 소스와 빌드 결과이며, 백엔드·DB·계정·문제 데이터 변경을 포함하지 않습니다. APK 패키지와 최종 실기기 확인 결과는 [변경 이력](./PATCH_NOTES.md)에 검증된 범위별로 기록합니다.
